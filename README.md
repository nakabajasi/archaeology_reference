# Archaeology Reference V0.1

紙の図面にスマホをかざすと、図面の元になった遺構・遺物の3Dモデルが図面の上に重なって出るウェブサイト。
資料情報と注記（遺構線と注釈）も見られる。GitHub Pages に置くだけで動き、サーバーでの処理や外部への通信はない
（使うライブラリ three.js・MindAR は `lib/` に同梱）。

## できること

- **図面にかざす**（`ar.html`）：図面を見つけると、3Dモデルを図面と同じ位置・縮尺・向きで重ねて出す。
  図面から外れるとモデルは消え、映し直すとまた出る。
  - 「透かす」でモデルを半透明にして下の図面と見比べる。「形だけ」で写真の色を外し、凹凸だけを見る。
  - 「注記」をタップすると遺構線が現れる。遺構線をタップすると注釈（遺構一覧表の内容）が参照できる。
  - 下のパネルに資料情報（遺跡名・出典など）が出る。
  - うまく映せていないときは、画面の上に注意が出る（「ゆっくり動かしてください。」「画像に近すぎます。離れてください。」
    「画像認識が不安定です。」）。
- **3Dだけ見る**（`viewer.html`）：図面やカメラが無くても、図面の上に置いたモデルと注記を見られる。
- **注記一覧**（`notes.html`）：注記を表で一覧する。CSV で保存・印刷できる。
- **リンクを渡す**：資料ごと・注記ごとのリンクを作れる（開くとその資料・注記を選んだ状態で始まる）。
- **展示用シート**（`tools/sheet.html`）：図面・QRコード・使い方を1枚にして印刷する。

iPhone は iOS 16.4 以降の Safari で動く。LINE や X のアプリの中のブラウザでは、カメラが動かないことがある。

## 作成手順

自分の図面とモデルで同じものを作る手順。差し替えるのは `data/` の中のファイルだけで、プログラムは書き換えない。

### 0. 用意するもの

| ファイル（`data/` に置く） | 中身 | 必須 |
|---|---|---|
| `image.jpg` | 図面画像。**印刷するものと同じ画像** | ○ |
| `model.glb` | 3Dモデル（図面画像と同じ座標で作る。手順2） | ○ |
| `items.json` | 台帳（題名、図面画像の実寸など。手順3） | ○ |
| `all.mind` | 図面を見つけるためのデータ（このサイトの管理用ページで作る。手順5） | ○ |
| `annotation.glb` | 注記の図形（遺構線）。手順6 | 無ければ注記なし |
| `annotation.csv` | 遺構一覧表。手順6 | 無ければ図形だけを名前で出す |
| `meta.csv` | 資料情報。手順7 | 無ければ出さない |

使う道具：Blender、GitHub のアカウント、Python が入ったパソコン（手元で開くため）。

### 1. 図面画像を用意する

- 印刷するのと同じ画像を `data/image.jpg` にする。後から画像を変えると、印刷した紙に反応しなくなる。
- 画像全体の**実寸（横・縦、m）**を控える。縮尺 1/80 の図面を 240dpi で画像にしたなら、
  画素数 ÷ 240 × 25.4 ÷ 1000 × 80。
- 白地に細い線だけの図面は見つけにくい。手順5で目安が出るので、だめなら網掛けや写真の入った図面を選ぶ。
- 縮尺の小さい図面（遺構配置図など）は、1つの遺構が紙の上で小さくなって見にくい。個々の遺構の平面図（1/40〜1/60 など）が向く。

### 2. 3Dモデルを図面に合わせて書き出す

モデルの座標は**図面画像の左下が原点、右が X、上が Y、単位 m**（Blender の座標）。

1. Blender で図面画像を板（平面）として読み込み、大きさを実寸（横・縦 m）にして、**左下の角が原点**に来るように置く
   （中心が原点の板なら、横の半分・縦の半分だけ動かす）。
2. その上に3Dモデルを置き、図面に重なるように位置・向きを合わせる（動かすのはモデル。板は動かさない）。
3. モデルだけを選んで glTF（.glb）で書き出す。「**+Y上**」は入れたまま（既定）。
4. 重いと読み込みに時間がかかるので軽くする（目安：テクスチャ 2048px 以下、5MB 前後）。
   ```
   npx @gltf-transform/cli resize in.glb a.glb --width 2048 --height 2048
   npx @gltf-transform/cli draco a.glb model.glb
   ```
5. `data/model.glb` に置く。

Blender で合わせられないモデルは、管理用ページの「2. 位置合わせ」（`tools/align.html`）で画面上で合わせられる。

### 3. 台帳（data/items.json）を書く

```json
{
  "site": {
    "title": "Archaeology Reference",
    "lead": "紙の図面にスマホをかざすと、図面の元になった遺構の3Dモデルが重なって出ます。",
    "edition": "2026-11-08"
  },
  "targets": [
    { "title": "○○古墳1トレンチ平面図", "realWidthM": 19.0317, "realHeightM": 16.5467 }
  ],
  "items": [
    { "title": "1トレンチ", "display": { "mode": "plan", "ground": "top" } }
  ]
}
```

| 項目 | 内容 |
|---|---|
| `site.title` / `lead` | 一覧ページの見出しと説明 |
| `site.edition` | データの版（日付など）。一覧・パネル・注記一覧に出る。データを直したら更新する |
| `targets` の `title` | 図面の名前 |
| `targets` の `realWidthM` / `realHeightM` | 図面画像全体の実寸（m）。手順1で控えた値 |
| `items` の `title` | 資料の名前（`meta.csv` に「資料名」があればそちらを出す） |
| `display.mode` | `plan`＝平面図に重ねる（遺構）／`stand`＝紙の上に立たせる／`lay`＝正面図に重ねて寝かせる（遺物） |
| `display.ground` | 紙の面に合わせる高さ。`top`＝モデルの上端（遺構の検出面が紙に来る）、`bottom`＝下端 |

「+Y上」を外して書き出したモデルは、`items` に `"model": { "rotationDeg": [-90, 0, 0] }` を足す。

### 4. 手元で開いて確かめる

このフォルダで `python -m http.server` を実行し、`http://localhost:8000/` を開く。
カメラは公開した後（HTTPS）でしか動かないので、手元では「3Dだけ見る」・注記一覧・管理用ページで確かめる。

### 5. 図面を見つけるためのデータ（all.mind）を作る

1. 管理用ページ `http://localhost:8000/tools/` の「1. 認識用データを作る」で「作成する」を押す。
2. 「all.mind を保存」で保存し、`data/all.mind` に置く。
3. 表の「判定」で、図面が見つけやすいかの目安が出る。最終的には印刷した紙とスマホで確かめる。
4. 同じページの「0. ファイルの確認」で、ファイルがそろっているか、食い違い（`all.mind` と図面画像の縦横比、
   モデルと図面の位置など）が無いかを確かめる。

図面画像を差し替えたときは、`all.mind` も作り直す。モデル・注記・表は上書きするだけでよい。

### 6. 注記を付ける（無くてもよい）

現場の図面（ベクトルデータ）と遺構一覧表をそのまま使う。図形と表は「**オブジェクト名 ＝ 表の遺構番号**」でつなぐ。

**図形（annotation.glb）**

1. 手順2の Blender のファイル（無ければ `model.glb` を読み込む）に、図面のベクトルデータを読み込んで重ねる。
   モデルは動かさない。
2. 読み込んだカーブはメッシュに変える（オブジェクト → 変換 → メッシュ）。カーブのままでは書き出されない。
3. 線を地表に沿わせる。
   - 長い線は頂点が少ないと地面を突き抜けたり浮いたりするので、先に細分化する（10〜20cm ごとに頂点が来るくらい）。
   - シュリンクラップ モディファイアーを付ける（対象＝モデル、方式＝投影、軸＝Z、マイナスとプラスの両方、オフセット 0.02 m）。
     表面にぴったり付けると線が埋もれるので、少し浮かせる。
   - モデルの表面より下に入った部分は表示されない（地中の推定線などは、壁や地面の中に隠れる）。
4. オブジェクト名を遺構番号にする（`SK02`、`円筒埴輪No.1` など）。1つの遺構を複数の図形で描くときは、
   `SK02.001` のように末尾に番号を付ければ1つの注記にまとまる。
5. 図形だけを選んで glTF（.glb）で書き出し、`data/annotation.glb` に置く。設定：
   - 含む → **選択したオブジェクト**
   - データ → メッシュ → **ルーズエッジ** と **ルーズポイント** を入れる（入れないと線と点が消える）
   - データ → メッシュ → **モディファイアーを適用** を入れる
   - 「+Y上」は `model.glb` と同じにする。圧縮はかけない

図形の種類は形で決まる：エンプティ・1点＝点、開いた線＝線、閉じた線・面のあるメッシュ＝面。

**表（annotation.csv）**

遺構一覧表を CSV で保存して `data/annotation.csv` に置く（Excel の「CSV」でも「CSV UTF-8」でもよい）。

| 列 | 使われ方 |
|---|---|
| 左端の列 | 遺構番号（図形のオブジェクト名と合わせる）。**左に別の列を足さない** |
| 「種別」「種類」「分類」 | 注記のまとまり（画面で出す・消すを切り替える単位）。無ければ点・線・面ごと |
| 「備考」「説明」 | 注釈の説明 |
| 「名称」 | 画面に出す名前。無ければ遺構番号 |
| そのほかの列 | 列名のまま項目として出る（空の欄は出さない） |

- 全角・半角、大文字・小文字、空白の違いは同じ番号とみなす（`ＳＫ０２` と `SK02` は同じ）。
- 表に無い図形（調査区の境界など）は表示しない。注記一覧は表の行の順に並ぶ。
- 表の上に表題などの1セルだけの行があってもよい。
- 管理用ページの「4. 図形と遺構一覧表の照合」（`tools/match.html`）で、つながらなかった図形と行を確かめる
  （打ち間違いの候補も出る）。

### 7. 資料情報を書く（無くてもよい）

`data/meta.csv` を Excel で書き、「CSV UTF-8」で保存する。

| 項目 | 内容 |
|---|---|
| 資料名 | ○○古墳1トレンチ |
| 遺跡名 | ○○古墳 |
| 所在地 | ○○県○○市 |
| 出典 | ○○市教育委員会 2024『○○古墳発掘調査報告書』 |
| URL | https://… |
| 注意書き | 図面の転載を禁じます。 |

- 1列目が項目名、2列目が中身。上から順にパネルと注記一覧に出る。項目は自由に足す・消す・並べ替えてよい。中身が空の項目は出ない。
- 「資料名」はパネルと注記一覧の見出しに、「注意書き」は項目の下に目立つ色で出す一文になる（どちらも項目としては出ない）。
- 中身が URL だけの項目は、押せるリンクになる（新しいタブで開く）。

### 8. 公開する（GitHub Pages）

1. このフォルダの中身を、隠しフォルダ（`.github/`）も含めて GitHub のリポジトリの最上位に置いて push する。
2. リポジトリの Settings → Pages → Build and deployment の **Source を「GitHub Actions」** にする。
3. `main` に push するたびに、Actions の「Pages に公開」が動いて公開される（1〜2分）。
   `https://<ユーザー名>.github.io/<リポジトリ名>/` で開く。
4. 一覧ページの一番下に版（「V0.1（版の印）」）が出る。括弧の中は公開した日時なので、新しい版になったかをここで確かめる。

公開のたびに、ブラウザに残った前の版のファイルを使わないよう自動で切り替わる（キャッシュを消す操作は要らない）。

図面画像は公開サイトから誰でも取り出せる。公開できない図版は、台帳の `targets` に `"viewerImage": false` を書いて
「3Dだけ見る」に図面を出さないようにし、`image.jpg` はリポジトリに入れない（手順5は手元で済ませ、
`all.mind` と台帳だけを公開する）。

### 9. 展示用シートを印刷する

管理用ページの「3. QRコードと展示用シート」（`tools/sheet.html`）に公開先の URL を入れて印刷する。
印刷した後は、公開先の URL（QRコードに入る）と図面画像を変えない。

## 図面・資料を増やすとき

1. 台帳の `targets` に図面を、`items` に資料を足す。図面と資料にはそれぞれ `"id"`（英数字）を付け、資料には載っている図面の `id` を `"target"` で書く。
2. 2つ目からはファイルをフォルダに分ける：資料のファイル（`model.glb`・`annotation.glb`・`annotation.csv`・`meta.csv`）は
   `data/<資料の id>/`、図面画像は `data/<図面の id>/image.jpg`。1つ目に `"folder": "data/"` を書けば、今のファイルは動かさずに済む。
3. `all.mind` は図面が何枚でも `data/all.mind` の1つ。手順5で作り直す（`targets` の並び順が中の順番になる）。

## 使うときの注意

- 斜めから見られるのは、真上から65°傾けたくらいまで。
- スマホのカメラは近すぎるとピントが合わない（機種により 10〜15cm より近いと合わない）。
  近くで見失ったら、少し離して図面の広い範囲を映すと早く戻る。
- 同時に追う図面は1枚。
- 追跡の細かい設定（揺れ止め、注意書きを出す条件など）は `js/tracking.js` の `TRACKING_DEFAULTS` に説明がある。
  台帳の `"tracking": { … }` か URL（例 `ar.html?shakeHold=3`）で変えられ、`ar.html?debug=1` で開くと判断に使っている数が画面に出る。
